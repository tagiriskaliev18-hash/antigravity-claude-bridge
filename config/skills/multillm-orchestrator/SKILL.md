# Multi-LLM Orchestrator & Router Protocol

Эта инструкция определяет, как Claude Code обязан взаимодействовать с внешней сетью моделей через MCP-шлюз `multillm-bridge` (`mcp__multillm-bridge__multillm_ask`, `mcp__multillm-bridge__multillm_review`).

## 1. Карта ролей и моделей в сети

| Модель | Роль в системе | Тариф / Стоимость | Когда использовать |
| :--- | :--- | :--- | :--- |
| **DeepSeek V4.1 Flash** | *Рабочая лошадка* | 10M Пул (Xyvero) | Рутина, бойлерплейт, верстка, генерация тестов, рефакторинг |
| **Claude Opus 5.5** | *Главный Архитектор* | Личная подписка | Финальная сборка, архитектурные решения, системный дизайн |
| **GPT-6 Astra / Sol** | *Второй Эксперт* | Пул OctavAPI | Альтернативный анализ сложных алгоритмов, консилиум |
| **DeepSeek V4 Pro** | *Глубокий Аналитик* | 5M Пул (CVC) | Поиск скрытых багов в критической логике |
| **Qwen 3.8 Flash** | *Быстрый Скриптер* | 5M Пул (CVC) | Написание вспомогательных bash/ps1 скриптов, regex |

## 2. Алгоритм правильной работы (Workflows)

### Сценарий А: Генерация объемного кода (Draft & Polish)
1. Если задача требует написания большого объема шаблонного кода (модели данных, CRUD-роуты, CSS-стили, тесты):
   - **Не трать квоту Opus 5.5.**
   - Вызови `mcp__multillm-bridge__multillm_ask` с `model: "deepseek-v4.1-flash"`, передав четкое ТЗ.
   - Получи готовый черновик от DeepSeek.
   - Проверь его своим интеллектом Opus 5.5, отшлифуй и аккуратно вставь в проект точечным патчем.

### Сценарий Б: Архитектурный Консилиум (Consilium)
1. Когда пользователь спрашивает «как лучше спроектировать систему?» или при старте нового модуля:
   - Сформулируй свой вариант архитектуры (Opus 5.5).
   - Параллельно вызови `mcp__multillm-bridge__multillm_ask` с `model: "gpt-6-astra"` или `"deepseek-v4-pro"`.
   - Сопоставь два решения, выдели сильные стороны обоих и выдай пользователю итоговый синтез.

### Сценарий В: Перекрестное Код-Ревью (Cross-Check)
1. Перед коммитом или после масштабных правок:
   - Вызови `mcp__multillm-bridge__multillm_review` с `model: "deepseek-v4.1-flash"`.
   - Сравни выводы независимого ревью со своими правками.

## 3. Железные правила экономии токенов
1. **Никаких полных перезаписей:** Никогда не выводить весь файл на 500+ строк. Использовать только замену целевых блоков (`sed` / `diff` / патч).
2. **Исключение мусора:** Запрещено считывать в контекст логи (`*.log`, `*.txt`), дампы баз (`*.sqlite`, `*.db`), кэши сборки (`dist`, `build`, `__pycache__`).
