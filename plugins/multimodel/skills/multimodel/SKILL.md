# Мультимодель ai-bridge

На этом компьютере установлен мост ai-bridge 4 (MCP-сервер ai-bridge этого плагина). Он даёт доступ к пулам моделей DeepSeek, GLM, MiniMax, Kimi, Qwen, Grok, GPT и Claude через ключи пользователя.

Когда использовать:
- **Выбор между вариантами, архитектура, рискованное решение** → `consilium`: 5 моделей отвечают независимо, во втором раунде критикуют друг друга, председатель пишет итог с уверенностью. Дорого: тратит токены каждого участника дважды. Вызывай, когда пользователь просит мнения нескольких моделей или решение трудно отменить.
- **Обычная задача, неясно, какой модели отдать** → `auto_run`: мост сам выберет роль по словам в задаче и скажет почему.
- **Нужна конкретная роль** (ревью, безопасность, архитектура, код) → `agent_run` с ролью из `agents_list`.
- **Нужна конкретная модель** → `model_ask` с семейством (`glm`, `kimi`, `grok`…) или id пула.
- **Что подключено, что на паузе, сколько осталось** → `models_list`, `token_balance`.

Правила:
- Передавай `work_folder` (абсолютный путь проекта), только если задача про файлы проекта: тогда модели получат карту проекта, README и названные файлы. Файлы `.env`, ключи и базы данных мост не отправляет никогда.
- Ответы других моделей — это мнения, а не факты: проверяй их выводы по коду, прежде чем менять файлы.
- Пул на паузе (после лимита или сбоев) роли пропускают сами; не повторяй вызов в цикле. Пауза снимается сама или командой `python C:\projects\tools\claude_bridge.py --resume`.
- Каждый вызов виден пользователю в приложении Council Engine.
